# Pre-registration: confirmatory re-run, 2026-10-18

Committed before the sweep. Anything run after the sweep is exploratory and is
labeled so.

**Why.** On 2026-10-17 the server arm was as accurate as Claude with Bash + R
(34 vs 33 of 34 headline questions right in every run) but cost 1.8 times as
much per answer ($0.051 vs $0.028 median). `diagnose.py` on those 240 tool-arm
transcripts puts 86% of the gap ($0.025 per run, mean) in cache writes:

- **Server instructions, ~1,100 tokens per run.** Claude Code 2.1.302 puts
  them in a system message after the user's question, beside the per-run
  working directory, so they are never in the cached prefix. Seen in the
  request body through a logging proxy; in the transcripts, the first API
  call writes 1,477 tokens (median) to the cache in the server arm against
  345 in the alt arm, on the same questions. Tool definitions (~3,300
  tokens) are in the cached prefix and cost little.
- **Tool results, ~1,300 tokens per run.** Server results averaged 3,380
  characters a run (alt: 58), mostly 17-digit floats repeated per cycle.
- Output tokens (thinking and a longer reply) are the rest: 898 vs 747 mean.

**Server under test.** `git+https://github.com/musharna/breedsim-mcp@7038ec03f03e60b444a633bf2ae7343a359f1c5a`,
unreleased (it still reports version 0.5.1). Changes from 0.5.1: instructions
cut from 3,106 to 357 characters (guidance moved into the tool descriptions;
a note to call tools by their `mcp__breedsim__` name), every float in a
response rounded to 4 significant figures, and `final_only` on `run_program`
and `compare_programs`. Dependencies are resolved with `--exclude-newer
2026-10-17`, which gives the 10-17 sweep's mcp 2.3.0, rpy2 3.5.17 and numpy
2.5.4 on CPython 3.14.3. AlphaSimR 2.1.0 for the key, the server and the alt
arm (`run.py` refuses any other).

**Arms.** Both re-run with the 10-17 prompt, system prompt, isolation and
tools: `alt` (Bash with R + AlphaSimR and Python, Read, WebSearch, WebFetch)
and `mcp` (this server only). For each rep, each question runs alt and then
mcp. The bare arm is not re-run. Model claude-opus-5-5 in Claude Code
2.1.302, `--workers 1`. One harness change: the repository's virtualenv is
removed from the arms' environment (`run.py clean_env`), so the alt arm's
`python` cannot import breedsim_mcp.

**Questions, reps, scorer.** The 40 questions in `questions.json`, unchanged,
3 reps per arm: 240 runs. Scorer `score.py` and the validity rule
`analyse.py invalid_reason`, both unchanged. The headline is the 34 questions
outside the probability category, as on 10-17.

**Primary endpoint.** Median cost per answer (`total_cost_usd`), mcp vs alt,
over the 34 headline questions × 3 reps. Every run counts, valid or not.

**Win rule** (from the 10-18 decision ledger):

1. Non-inferior: mcp's questions right in all 3 reps ≥ alt's − 2 (headline).
2. Better: the exact two-sided Wilcoxon signed-rank test over the 34
   questions, on each question's mean cost per answer (mcp − alt), gives
   p < 0.05 with more questions cheaper under mcp, AND the 95% bootstrap CI
   (10,000 resamples of questions, seed 1) of median(mcp) − median(alt) has
   its upper end below 0.

- **Win**: 1 and 2 hold.
- **Tie**: 1 holds, 2 does not, and mcp is not significantly dearer.
- **Loss**: 1 fails, or the test gives p < 0.05 with more questions cheaper
  under alt AND the CI's lower end is above 0.

All of it is `analyse.py`'s `headline.cost_mcp_vs_alt` and
`headline.mcp_vs_alt`.

**Expected, stated in advance.** If the two cache-write items were removed
entirely, mcp would cost about $0.029 per answer, the same as alt on 10-17;
the reply and thinking tokens are not addressed. A tie is the likely result,
a win is possible only if alt's cost also rises or mcp's replies shorten.

**Usage-limit gate.** The sweep starts only when the newest transcript shows
the five-hour usage window under 0.50 and the seven-day window under 0.80.
`run.py` sleeps until the window resets whenever a run's transcript shows
five-hour ≥ 0.85 or a rejected request, and logs each pause to
`pauses.jsonl`. A row the API ended before any model answer (a rejected
request and no assistant message: `api_failure`, read from the transcript,
never from the reply) is a harness failure: after the sweep,
`run.py --drop-api-failures` moves those rows aside and the resumed sweep
runs each triple again, once. A row that fails that way twice stays and
counts as invalid. No other retries; an interrupted sweep is resumed, not
restarted, and not stopped early on interim results.

**Secondary, descriptive (no rule).** Accuracy (right of 102, right in all
reps) with McNemar and bootstrap CIs; the same on all 40 questions; median
seconds per answer; the `diagnose.py` token breakdown per arm against 10-17;
mechanism readout from `diagnose.py --mechanism`: runs using `final_only`, and
tool calls made by a bare name. The instruction cut and the rounding apply to
every mcp run; `final_only` is opt-in, so if no run uses it, it was not
tested.

**Controls, all active.** The oracle check in `run.py` before the sweep; the
no-LLM baselines in `baselines.tsv` (unchanged); the validity rule; the leak
scan over every transcript; paired tests and bootstrap CIs as above.
